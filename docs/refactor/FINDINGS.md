# Findings register

Bugs, surprises and strange design decisions found in the code, tests or build while working through the plan. `PROGRESS.md` says what each chunk did; this file keeps the issues themselves in one place, so they are not lost in old log entries.

Rules (also in `PLAN.md` § Session protocol):
- Add an entry when you find something, even if it is out of scope for the chunk. Give it the next free ID; never reuse IDs.
- Kinds: **bug** (wrong behaviour), **surprise** (correct but unexpected, and likely to trip someone up), **design** (a strange or questionable decision worth revisiting).
- Don't fix a finding that changes observable output (stdout, stderr, outputs, exit codes) inside a refactor chunk. Record it, and ask the user before fixing it in its own commit.
- When an entry is fixed or settled, move it to § Closed with the commit or chunk.

## Open

- **F1** (bug, found C2): `--progress` prints one `\r N%` line per step instead of one per percent. `print_progress` takes `last_percent` by value, so the caller's copy never changes (`model/Simulation.cpp`). Fixing it changes stderr only. Planned for M3 if the user agrees.
- **F2** (bug, found S1): after any caught exception, `main()` calls `perror("OpenMalaria")` whenever `errno != 0` (`model/main.cpp:119`). `errno` is often left over from an earlier, harmless failed file lookup, so error reports end with an unrelated `OpenMalaria: No such file or directory`. Changes stderr; candidate for M3 or I2.
- **F3** (surprise, found S1): invalid input can be reported as a C++ bug. `popSize="-5"` in `scenario1` gives `Code error: initialKappa is invalid … This is likely an error in the C++ code. Please report!` (from `NonVectorModel.h:107`), with exit 75, instead of an input-validation error. Scenario values aren't checked before they reach model code. Relevant to E (config boundary validation).
- **F4** (bug, found S1): `test/run.py` `findFile` returns from inside its loop, so it gives an arbitrary existing candidate from a `set`, not the newest as intended. Harmless while only one `openMalaria` exists in the build dir.
- **F5** (bug, found S1): `test/run.py` prints "No output 'output.txt'; error messages:" and then reads `stderr.txt` but throws the content away (`se.read()` is never printed). openMalaria doesn't write `stderr.txt` anyway, so the branch is dead.
- **F6** (design, found S1): `test/run.py` replaces `sys.path[0]` with `util/` at import time, so any script that imports it loses its own directory from the import path. `run_replicates.py` restores `sys.path` around the import.
- **F7** (surprise, found S1): binary survey output decoded by `binaryToText` lists all integer measures before the double ones. The rows match text output only when matched by (survey, group, measure), not line by line. `compareOutput.py` matches by key, so ctest's `--binary` mode is unaffected.
- **F8** (surprise, found A2): 6 of the 57 `test/scenario*.xml` files are not registered in `test/CMakeLists.txt` (2, 3, IPT, VT, MultiVecPopInterventions, VecLC*), some disabled for unknown reasons ("TODO: since when?"). They are not covered by any gate.
- **F9** (surprise, found B4): 4 CxxTest suites (AnophelesModel, DescriptiveInfection, ESCaseManagement, MosqLifeCycle) are not compiled, so renames and refactors can't reach them and they may have rotted. M9 ports or deletes them.
- **F10** (surprise, found M0): GSL is GPL-3.0-or-later and Xerces-C is Apache-2.0, so a distributed `openMalaria` binary is effectively GPLv3-only already, although the project says GPL-2.0-or-later. Bears on Decision 6.
- **F11** (surprise, found M0): `contrib/README.txt` is stale (CxxTest 3.10.1 under LGPL-2.1; the tree has 4.4 under LGPL-3.0). `DEPENDENCIES.md` is the source of truth.
- **F12** (surprise, found M0): `docker/Dockerfile` uses Ubuntu 22.04's CMake 3.22, below the new 3.24 minimum. It builds upstream's `schema-50` branch, so it is unaffected for now.
- **F13** (design, found M1): the `OM_CXXTEST_ENABLE` option now also enables the Catch2 tests. Rename it in M9.
- **F14** (design, found C2): stdout uses `std::endl` (flush on every line) in many places, and changing it would change the interleaving of stdout and stderr. It is kept with `NOLINT(performance-avoid-endl)` until M3 moves console output to spdlog.
- **F16** (bug, found S2; mechanism in F26, fix planned in V1): all four `ModelName*` scenarios (dynamic vector transmission, Namawala) abort for many seeds with `Code error: Transmission warmup exceeded 30 iterations!` (`model/Transmission/VectorModel.cpp:309`, exit 76). The scenarios' own `iseed="1"` works, so ctest never sees it. Seeds 1001–1020 (1001–1100 for NoOverrides): NoOverrides 62 of 100 failed, ManyOverrides 10 of 20, ModelOptionOverrides 8 of 20, ParamOverrides 16 of 20. The GaussianCopula scenarios, which have the same output size, did not fail for 20 seeds. It is reported as a C++ bug (F3) and followed by the stale-`errno` line (F2). S5 can't build N = 500 references for these scenarios without either more seeds (and a reference conditioned on convergence) or a model fix.
- **F17** (surprise, found S2): leave-one-out miss counts are heavy-tailed when cells are strongly correlated. ModelNameNoOverrides (N = 38, 67k non-zero-width cells): median 480 misses, mean 2127, max 11278, so the 99.9% threshold is about the maximum and a whole-run shift of up to ~11k missed cells would pass. scenario1 (N = 50, 838 non-zero-width cells): median 46, max 99. S6's power study should show whether the aggregates or a per-measure test are needed to catch such shifts. **S6:** confirmed. In the power study the power comes from the aggregates; e.g. Genotypes at 5% higher force of infection fails 98% of runs on aggregates while its miss count stays unremarkable (p ≈ 0.2). See F31.
- **F20** (surprise, found S3): with fewer than 99 replicates, rule (a) can never fail, because the smallest possible p is 1/(N + 1) > 1%. The generator warns and writes `max_passing_misses: unlimited`. Use N ≥ 100; S5 plans 500.
- **F22** (design, found S5): `run_replicates.py` records `commit` and `dirty` in `meta.json` from the source tree's state when each scenario starts, not from the source the binary was built from. Editing or committing tracked files while a long job runs changes what is recorded, even though the binary is the same. Only `binary_sha256` really identifies the build. In S5, scenario 12 was recorded as `dirty: true` because uncommitted Python edits were in the tree. Fix candidate: have CMake stamp the commit and dirty flag into the build dir at build time, and read that. Hit again in S6: scenario1's remade replicates were recorded `dirty: true` (uncommitted references and a new script in the tree), so they were remade once more from a clean tree.
- **F24** (bug, found S5): LifeNet1 and LifeNet2 abort for seed 1223 with `Error: SimpleMPD model: negative emergence at t=39887: -1.12842e+06. Check the seasonality …` (exit 64), after warmup. The other 499 seeds of 1001–1500 run. Both scenarios share the same SimpleMPD vector setup, so it is one cause. It is like F16: a seed-dependent model abort that ctest's fixed seed never hits. The input EIR seasonality is the same for every seed, so the negative emergence comes from stochastic state, which suggests the check (or the emergence calculation) is too strict for rare draws. S5 builds these two references from 499 replicates. The rerun seeds 2001–2005 that `check_scenario.py` uses should be checked to run. **S6:** seed 3095 aborts both too (fresh seeds 3001–3200, so 1 in 200), and with the LifeNet intervention removed 2 of 50 seeds abort (4032, 4047), all with the same SimpleMPD negative-emergence error.
- **F25** (surprise, found S5): `run_replicates.py` checks that an existing `OUT` dir was made by the same binary before it looks for finished seeds. A complete dir from an equivalent but differently-hashed build (e.g. another build dir of the same commit) is refused with exit 2, even though there is nothing left to run. Harmless, but a driver that loops over scenarios logs errors for them. Skipping the hash check when every requested seed is already present would fix it.
- **F26** (bug, found S5): AvailabilityFilter (300 people) aborts with `Code error: Transmission warmup exceeded 30 iterations!` (exit 76) for 64 of seeds 1001–1500 (12.8%), and for rerun seed 2004. It is the same cause as F16. `EmergenceRateAdaptiveFitter::estimate` measures the simulated S_v over one year of each 6-year round, rescales emergence by the full measured ratio, and stops only when a single round lands within ±10% of the target. Passing seeds 1001 and 1002 needed 25 and 23 rounds; failing seeds 1007 and 1009 hit the 30-round cap. So almost every seed is near the cap, and the noisy measurement from a small population tips some over. Why convergence takes ~25 rounds rather than a few is not yet known. V1 instruments the per-round ratio to find out.
- **F27** (bug, found S5): ExactNv0 (150 people, `USE_EXACT_NV0_SOLVER`) aborts with `The exact emergence solver produced negative emergence rates … smooth the EIR seasonality` (`CalcNvO.cpp`, exit 64) for 92 of seeds 1001–1500 (18.4%), and for rerun seed 2003. The input EIR is the same for every seed, so the message's advice does not fit. What varies is `laggedKappa`, the human infectiousness measured from the small simulated population during warmup. Where the target EIR falls steeply, the required emergence is near zero, and noise in kappa pushes some days below zero. Planned for V1.
- **F29** (surprise, found S5): SimpleMPDTest writes ctsout during warmup (`<continuous duringInit="true">`), so its ctsout length depends on the number of EIR calibration rounds: over seeds 1001–1500, 425 have 7448 rows, 65 have 7886, 7 have 8324 and 3 have 8762 (+438 = one 6-year round of 5-day steps). `generate_reference.py` refuses replicates whose cells differ, so SimpleMPDTest has no reference. It has the same root cause as F26 and is planned for V1.
- **F30** (design, found D2): the unit tests' `Human`s seed their RNGs from one process-wide master RNG (`UnittestUtil::createHuman`; before D2 the never-seeded global `master_RNG`). Each test's draws therefore depend on how many humans earlier tests created, so the CxxTest results depend on test order and on adding or removing a test. D2 kept this as is, to keep G-unit identical. Candidate fix (M9, when the suites move to Catch2): bind a fresh `MasterRng(0, 0)` per test, and re-derive any expected values that change.
- **F31** (design, found S6): the statistical check has little power against small, real changes. A 20% higher force of infection moves the mean prevalence by 1.9–2.5 single-run SDs in ten scenarios, yet the default rerun rule detects it with ≥ 80% power in only 2 of 44 scenarios (Genotypes, Penny), and `--replicates 20` in 10. The reason is structural: each run is judged against intervals that hold 99% of single runs, and `--replicates` counts failing runs rather than testing where the K runs lie as a group. A test of the K-run mean of each aggregate against the reference mean and SD would see a 1-SD shift at K = 20 as z ≈ 4.5. Matters for D2b/M4/M8, whose only gate is G-stat: a pass there means no large change, not equivalence. Related: with 44 `stat_*` tests at 0.16% each, a correct draw-changing build has about a 9% chance that some test fails falsely. Candidate follow-up (needs the user's decision, since it changes the S3 method): a mean-shift test in the `--replicates` mode, re-validated on the kept S6 runs (`build-rework/stats-s6/`). Details in `test/stats/README.md`.

## Closed

- **F23** (bug, found and fixed D1): `util/rename_module.py` missed uses inside `assert(...)` and `#ifndef NDEBUG` blocks, because clang-tidy runs on the Release compile database, where `NDEBUG` removes them. The text pass renamed `sim::nowOrTs1` → `sim::now_or_ts1` there, but not the class qualifier `sim::` → `Sim::`. The Release build and the token check passed; a Debug build would not have compiled. Fixed in bda40963: the tidy runs add `-UNDEBUG`, and the text pass also renames a renamed class used as a qualifier, for other disabled blocks (e.g. `#ifdef WHVivaxSamples`). The B4 PkPd rename had no such uses. `util/modernize_module.py` has the same Release-only view, which only means it skips assert bodies, not that it breaks them.

- **F15** (design, found S2): the plan's rule "zero-width cells must match exactly" (§ Statistical tests (2)) would fail often by chance. Many zero-width cells are rare events, e.g. `nTreatments` counts in one age group and survey, that were 0 in every reference replicate but are not impossible. Leave-one-out on the scenario1 replicates (N = 50): in 20 cells one replicate differs from the other 49 identical ones, so 19 of the 50 replicates would fail the exact-match rule against the other 49. ModelNameNoOverrides (N = 38): 24 of 38 replicates, 8731 cells. The generator records this as `loo_zero_width_failures` in each reference. S3 must decide the rule, e.g. count a zero-width mismatch as an ordinary miss (the leave-one-out threshold already includes them), and keep exact matching only for cells that are deterministic by construction. **Settled in S3** (46cef63b, 2b6281d6): the user chose a method with reruns (PLAN.md § Statistical tests (2)). Zero-width cells at 0 are ordinary misses; only *fixed* cells, constant at a non-zero value or NaN, must match (rule (c)). Rule (c) is needed because a miss count alone would let a deterministic error in a few cells through: each wrong cell adds only one miss. Leave-one-out on scenario1 at N = 500: 0 replicates fail rule (c); 1600 fresh seeds: 0 failures from it.
- **F21** (bug, found and fixed S3): the generator wrote numpy's sample SD for constant cells, which is ~1e-14 rather than 0 for values such as 3.0425. The checker's report then showed z-scores near 1e14 for fixed cells. Fixed in 012e38d8 (SD 0 when min == max), and the scenario1 reference was regenerated.
- **F18** (surprise, found S3): over 1600 fresh seeds of scenario1 (2001–3600), aggregates failed 23 runs (1.4%), against a nominal 1% for the 99% family (~16 expected). The 0.25% tails of each aggregate interval are estimated from about one replicate at N = 500, so they are noisy. The whole per-run rate was 31 of 1600 (1.9%), in line with the 2% design rate. S6 should check this on more scenarios and, if needed, widen the aggregate interval or derive it from more replicates. **Settled in S6** (350fdaf3, c9f46c93, ecdac231): the cause is the quantile method. Type 7 at p = 0.001–0.0025 is too narrow for one new run (its expected coverage is (1 + (N − 1)p)/(N + 1), about twice p here). The aggregate intervals now use type 6, whose expected coverage is p. Leave-one-out over 43 scenarios: 1.59% → 1.09%; 8798 fresh runs: 1.10%.
- **F19** (surprise, found S3): scaling a scenario's EIR is caught through the fixed `input EIR` cells, which echo the input, not through the statistics. EIR × 1.1 fails every run on rule (c), but only 3 of 6 runs on the miss count. S6's power study should perturb parameters that are not echoed into the output. **Settled in S6:** the power study perturbs the force of infection in a throwaway build (`test/stats/foi_scale.patch`), which is not echoed anywhere, plus one intervention switched off.
- **F28** (design, found S5): rule (c) of the statistical check (a cell constant at a non-zero value in every replicate must match) gives about 10% per-run false failures in 2ITNs (48 of 500 in leave-one-out), IRS30 (51) and Rach5IC (56). Every case is the ctsout `recent births` column: births per 5-day step are 2 in all but one replicate, which has 3. That is a rare event, not a deterministic echo like `input EIR`, so it is F15 again for non-zero values. All other references are at 1–4%. Left for S6 (see PLAN.md S6). Until then those three tests fail falsely about 10% × (1 − 0.9⁵) ≈ 4% of the time, and only when a change alters their run-1 output. **Settled in S6** (350fdaf3, c9f46c93): a cell is fixed only if every cell of its survey measure or ctsout column is constant across the replicates. Leave-one-out per-run failures: 2ITNs 48 → 8, IRS30 51 → 6, Rach5IC 56 → 7 of 500. Rule (c) failed none of 8798 fresh runs. Lost as fixed cells: the `recent births` cells, one all-NaN `simulated EIR` cell in 1, BSV, PEV and TBV, and 2 nHost cells in 9; they are now ordinary misses.
